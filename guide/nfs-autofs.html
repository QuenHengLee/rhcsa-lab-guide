NFS 與 autofs 圖解

這題把兩個東西串在一起:NFS 讓一台機器把目錄「分享」到網路上,另一台掛來用;autofs 讓這個掛載變成「進去才掛、閒置就卸」的自動化。這頁把兩者的機制畫出來,再對照到 servera / serverb 的實作。

1NFS:把目錄分享到網路上

NFS(Network File System)讓「伺服器」把某個目錄匯出(export),其他「用戶端」就能把它掛載到自己的目錄樹裡,像本機資料夾一樣讀寫——檔案其實一直在伺服器上。

前提:serverb 必須開著——它是檔案的來源,關著的話 servera 這邊掛不起來。查它有沒有匯出:showmount -e serverb。

2autofs:進去才掛、閒置就卸

你也可以用 mount 或寫 /etc/fstab 把 NFS 目錄「一直掛著」,但這題要的是 autofs——只有真的有人進入那個目錄時才掛載,一段時間沒人用就自動卸載。

fstab / mount(一直掛著)autofs(進去才掛)
何時掛載開機時就掛有人存取才掛
沒人用時還是掛著、佔資源自動卸載
伺服器關機時開機可能卡住等它不受影響(要用才連)
適合永遠都要用的掛載偶爾用、或很多個的網路目錄
本題規則:必須用 autofs,不可以寫死 /etc/fstab。評分會抓——在 fstab 硬掛一行雖然「也能掛上」,但不符合題目要求,不會過。

3間接對映:兩個檔案的接力

autofs 怎麼知道「/rhome/remoteuser1 要去掛 serverb 的哪個目錄」?靠兩個設定檔接力:master 檔說「哪個母目錄交給哪張對映表管」,對映檔說「這個子目錄對到哪個遠端來源」。

4實作:三步設定 + 一步驗證

在 servera 上操作(serverb 已匯出好、保持開機)。對照上面的圖:第 1、2 步就是建那兩個接力檔。

# 0. 裝套件(minimal 安裝可能沒有)
# dnf -y install autofs nfs-utils

# 1. master 檔:把母目錄 /rhome 交給 /etc/auto.rhome 管
# echo '/rhome  /etc/auto.rhome' > /etc/auto.master.d/rhome.autofs

# 2. 對映檔:key remoteuser1 → serverb 的來源
# echo 'remoteuser1  -rw  serverb.lab.example.com:/rhome/remoteuser1' > /etc/auto.rhome

# 3. 啟用(--now = 現在啟動;enable 保證重開機後仍有效)
# systemctl enable --now autofs
# 4. 驗證:先「踏進去」觸發掛載,再確認來源
# ls /rhome/remoteuser1          # 看到 welcome.txt = 掛載被觸發
# findmnt /rhome/remoteuser1     # 確認來源是 serverb 的 NFS
# lab grade nfs-autofs
四個評分必中的點:① autofs 要 enable(不只 start),重開仍有效;② 用 /rhome 的間接對映;③ 不可寫死 fstab;④ 掛載真的來自 serverb。收尾:lab finish nfs-autofs。

5卡住了?常見原因

症狀檢查/原因
ls /rhome/remoteuser1 沒東西 / 掛不上serverb 沒開,或沒匯出:showmount -e serverb 看得到 /rhome 嗎?ping serverb 通嗎?
改了設定檔沒生效沒重載 autofs:systemctl restart autofs(改對映檔後要重啟才讀新內容)
重開機後失效只 start 沒 enable——用 systemctl enable --now autofs 一次到位
autofs 服務起不來對映檔語法錯,或套件沒裝(autofs / nfs-utils)

記住那個「空目錄」現象:autofs 平時不掛,ls /rhome 是空的很正常;一定要 ls 或 cd 那個子目錄本身(/rhome/remoteuser1)才會觸發掛載。別看到 /rhome 空的就以為失敗了。
