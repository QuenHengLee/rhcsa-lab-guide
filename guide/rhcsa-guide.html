RHCSA 實作題解手冊

你的 VirtualBox 教室(servera:ssh -p 2222 student@127.0.0.1、serverb:-p 2223)內建 34 題可自動評分的 RHCSA 練習。每題固定走同一套流程,本手冊給出每題的標準解法。除特別註明外,所有操作都在 servera 上以 root(sudo -i)執行(boot-rootpw 在 serverb)。

lab start 題目名 佈置環境+出題→ 動手解題→ lab grade 題目名 逐項檢查→ lab finish 題目名 清除還原

lab grade 可以重複執行,沒過就繼續改;lab describe 題目名 只看題目不動系統(中英雙語)。先看完題目、自己做過一輪,卡住再看本手冊的解法,效果最好。

循序規則:上一題沒完成,不能開始下一題。當某題已 lab start 但還沒「評分全 PASS」或 lab finish,再對「別題」下 lab start 會被擋下。要往下一題,先把手上這題 lab grade 到全綠、或 lab finish 收掉。(緊急覆寫:LAB_FORCE=1 lab start 題名,不建議。)這條規則逼你養成「做完、驗過、收乾淨」的節奏,正是考場該有的紀律。

本手冊的解題原則:最短能過關。所有解法都只保留「評分必要」的指令與選項,非必要的保險選項(如 -xdev、額外的 daemon-reload)一律省略——好記、好打、考場夠用。

tools-find

Find files by owner and collect them依擁有者尋找並收集檔案

perms-collab

Collaborative directory (setgid + sticky)setgid + sticky 協作目錄

servera

① 啟動

$ lab start perms-collab

建立 /home/accounting:群組 accounting 擁有、成員可讀寫進入、外人無權限、新檔自動繼承群組、成員只能刪自己的檔。真實考題和這題一樣只描述行為,不會給你權限數字——數字要自己推。

② 概念:特殊權限位的規則

chmod 的數字其實有四位:最前面一位是「特殊權限」,後三位才是熟悉的 owner/group/other。

chmod  3 7 7 0
       │ │ │ └ other
       │ │ └── group
       │ └──── owner
       └────── 特殊位:setuid=4、setgid=2、sticky=1(可相加)

三個特殊位「用在目錄上」的意義(考的就是這個):

setgid (2)  在此目錄建立的新檔/新子目錄,群組自動 = 目錄的群組
            → 對應題目「每個檔案自動群組擁有為 accounting」
sticky (1)  目錄內的檔案,只有「檔案擁有者」能刪或改名
            → 對應題目「成員只能刪自己的檔案」(範本:/tmp 就是 1777)
setuid (4)  對目錄無作用(用在執行檔上:以檔案擁有者身分執行,如 passwd)

推導本題數字:行為需要 setgid+sticky → 2+1=3;成員可讀寫進入 → group=rwx=7;擁有者照慣例全開 → 7;外人無權限 → 0。合起來 3770。

② 逐步解法

# mkdir /home/accounting
# chgrp accounting /home/accounting
# chmod 3770 /home/accounting

不想算數字,用符號法一樣過關:chmod 770 目錄 之後 chmod g+s,o+t 目錄(g+s=setgid、o+t=sticky)。兩種殊途同歸,考場挑順手的。

③ 驗證

# ls -ld /home/accounting
drwxrws--T. ... root accounting ...
    │  └ 群組 x 位變 s = setgid 生效
    └ 結尾 T = sticky(大寫因 other 無 x;/tmp 是小寫 t)
# stat -c '%a %G' /home/accounting   # 3770 accounting
# lab grade perms-collab

④ 收尾

# lab finish perms-collab

實測手感:su - amy 進去 touch /home/accounting/a.txt,再 ls -l 看群組是否自動變 accounting;換 su - ben 試著 rm a.txt,會被 sticky 擋下——這兩個動作做一次,setgid/sticky 就再也不會忘。

perms-umask

Default permissions with umask用 umask 設預設權限

servera

① 啟動

$ lab start perms-umask

讓 webdev 的新登入 shell 中,新檔 640、新目錄 750,而且登出再登入仍有效;其他使用者不受影響。題目通常只給你「640 / 750」這兩個目標權限,umask 的值要自己推。

② 概念:umask 為什麼是 0027

umask 是「從系統給的起始滿分裡扣掉」的遮罩。起始滿分是固定的:新目錄 777、新檔 666(檔案起始就沒有 x,系統絕不讓新檔自動可執行)。逐位相減:

              owner group other
目錄 777  −  umask = 750   →  7-0=7 · 7-2=5 · 7-7=0
檔案 666  −  umask = 640   →  6-0=6 · 6-2=4 · 6-6=0
                                   ┌──────────────┐
                          umask =  │ 0  2  7 │ → 0027
                                   └──────────────┘

三位的意義:owner 扣 0(自己全保留)、group 扣 2(拿掉 write,變唯讀)、other 扣 7(rwx 全拿掉,外人無權限)。最前面那個 0 是特殊權限位,umask 幾乎永遠寫 0,所以 umask 027 三位寫法完全等價。

反推口訣:一律用「目錄那組」算 → 777 − 目標目錄權限。因為檔案起始的 666 本來就沒有 x,「遮罩有沒有擋 x」在檔案上看不出來(6 遇到遮罩 6 或 7 結果都是 0),只有目錄的 777 才顯示得出完整遮罩。若題目只給檔案權限(如「新檔 640」),先翻成對應目錄權限(有讀寫的類別補上 x:640→750)再算 777−750=027。

② 逐步解法

# echo 'umask 0027' >> /home/webdev/.bashrc

一行搞定:寫進「webdev 個人的」.bashrc。RHEL 預設的 .bash_profile 會 source .bashrc,所以登入 shell 也吃得到。不要動 /etc/profile——那會影響所有人,評分會抓。

③ 驗證

# su - webdev -c umask   # 0027
# lab grade perms-umask

④ 收尾

# lab finish perms-umask

套路是「semanage fcontext 定規則(立法)+ restorecon 套標籤(執法)」。只用 chcon 改標籤撐不過 relabel,評分明確會抓這一點。

符號解釋:'/lab-content(/.*)?'

這個引號裡的東西是一段正規表達式(regex),semanage 用它比對「哪些路徑」要套這個標籤。逐塊拆解:

/lab-content # 字面路徑:目錄本身
(         # 群組開始
  /       # 一個斜線
  .       # . = 任意一個字元
  *       # * = 前一個東西出現 0 到多次 → 合起來「/任意字串」
)?        # ? = 整個群組出現 0 或 1 次(即「可有可無」)

合起來的意思:比對 /lab-content 這個目錄本身,以及它底下的所有東西(/lab-content/lab.html、/lab-content/sub/a.txt…)。關鍵是那個 ? ——有它,目錄「本身」和「內容」才會一起被涵蓋;少了它就只比對到底下的檔案、漏掉目錄自己。

記法:'/路徑(/.*)?' 是 fcontext 的固定慣用寫法,意思永遠是「這個目錄連同底下遞迴全部」。換題目只要改路徑(/web、/srv/www…),後面的 (/.*)? 照抄即可——不用真的懂 regex,當成一個「遞迴整包」的咒語背下來最省事。man semanage-fcontext 最底部的 EXAMPLES 也是這個寫法。

考場自救:man 手冊查法

語法記不清時,答案就在系統裡——man semanage-fcontext 最底部的 EXAMPLES 段有完整可抄的範例,連 (/.*)? 的寫法都直接給你。查法三招:

# man semanage-fcontext    # 按 G 直達最底部 EXAMPLES,照抄
# man -k semanage           # 忘記指令全名?關鍵字反查(= apropos)
# man 5 fstab               # 「設定檔格式」都在第 5 章

man 括號數字 = 章節:1 一般指令、5 設定檔格式、8 管理指令。撞名時要指定章節——man crontab 是指令用法,man 5 crontab 才是五個時間欄位的格式說明。閱讀導航:/字串 搜尋、n 下一個、G 跳到最尾、q 離開。若 man -k 查無資料,先跑 mandb 重建索引。

③ 驗證

# lab grade sec-selinux-fix

④ 收尾

# lab finish sec-selinux-fix
