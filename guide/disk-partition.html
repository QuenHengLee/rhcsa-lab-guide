磁碟分割圖解

一顆空白磁碟要變成可以放檔案的目錄,固定經過五層轉換;LVM 則是在分割區之上再疊一層「積木池」。這頁把每個機制畫出來,並對應到你 VM 裡的 storage 練習題與指令。

1大局:從磁碟到可用目錄的五層

每一層之間的轉換,就是一個指令——把這張圖背起來,storage 題就是照著箭頭打字。

# lsblk        # 隨時查看目前這五層的狀態(樹狀:磁碟→分割區→掛載點)
# blkid        # 查每個檔案系統的 UUID 與類型

2裝置名稱怎麼讀

/dev/sd a 2   →  sd=SATA/SCSI 磁碟  a=第 1 顆(b=第 2 顆…)  2=第 2 個分割區
/dev/vd b 1   →  vd=virtio 磁碟(KVM 虛擬機=真實考試環境)  b=第 2 顆  1=第 1 個分割區
/dev/nvme0 n1 p1 → nvme0=第 1 個 NVMe 控制器  n1=第 1 顆碟  p1=第 1 個分割區

規則:裝置名以「數字」結尾時(nvme0n1、mmcblk0),分割區編號前要加 p——所以是 nvme0n1p1 而不是 nvme0n11。以字母結尾的(sda、vdb)直接接數字:sda1、vdb1。你的練習碟是 NVMe 命名(/dev/nvme0n1、/dev/nvme0n2),真實考試是 KVM 虛擬機,練習碟通常叫 /dev/vdb——名字不用背,進場先 lsblk,哪顆是空碟一目了然。系統碟(這裡是 sda,考場是 vda)永遠不要碰。

3分割表:MBR vs GPT

分割表是磁碟開頭的一張「目錄」,記錄每個分割區從哪裡開始、到哪裡結束。兩種格式的差別決定了你能切幾塊、能用多大。

MBR (msdos)GPT
分割數量4 個主分割(3 主 + 1 延伸可再切邏輯分割)128 個,無主/延伸之分
磁碟大小上限2 TiB8 ZiB(實務上無上限)
分割表備份無磁碟尾端有備份
建立指令parted ... mklabel msdosparted ... mklabel gpt

4檔案系統:分割區裡的收納規則

分割區只是「一段原始空間」,還不能放檔案。檔案系統(file system)是把這段空間組織起來的規則:哪裡放資料、哪裡放索引(檔名、權限、擁有者、時間戳都記在這)。mkfs = make filesystem,就是把這套規則「鋪」到分割區上——所以又叫格式化,會清掉原有內容。

XFSext4VFAT
定位RHEL 預設,大檔與平行 I/O 強Linux 傳統通用格式跨平台交換格式(隨身碟、EFI 分割區)
建立mkfs.xfs /dev/vdb1mkfs.ext4 /dev/vdb1mkfs.vfat /dev/vdb1
線上放大xfs_growfs 掛載點resize2fs 裝置—
縮小不行!只能放大可以(需先卸載)—
Linux 權限/擁有者支援支援不支援(無 chmod/chown 概念)
fstab 類型欄寫xfsext4vfat
# lsblk -f        # 每個分割區用的檔案系統+UUID+掛載點,一眼看完
# mkfs.xfs -f /dev/vdb1   # -f:分割區上已有舊檔案系統時強制覆蓋

考場原則:題目指定什麼就 mkfs 什麼,別自作主張(你朋友那份考題就明確考了 ext4/xfs)。兩個好搭配 lvextend 記的點:-r 會自動挑對放大工具(XFS 用 xfs_growfs、ext4 用 resize2fs),所以擴充題一律 lvextend -r 最省事;以及 XFS 沒有縮小這條路——題目若真要縮小,那一定不是 XFS。

5掛載:目錄是通往磁碟的門

「掛載」= 把檔案系統的內容接到目錄樹的某個目錄底下,那個目錄就成了通往這顆碟的門。掛載前後的差別:

掛載前:                            掛載後:
/                                   /
├── etc/    ← 都在系統碟          ├── etc/       ← 還是系統碟
└── mnt/                            └── mnt/
    └── data/  ← 只是個空目錄          └── data/  ← 這裡面的一切
                                                   實際存在 vdb1 上!

由此推出的性質:掛載點目錄要先存在(所以流程裡永遠有 mkdir);掛哪個目錄是你決定的,目錄名沒有魔法;umount 只是關門,碟上的檔案不會消失;同一個目錄同時只能掛一個檔案系統。查詢對照:

# findmnt /mnt/data    # 問單點:這個目錄背後是哪顆碟?
# df -h                # 看全局:每個掛載點的容量與用量
# lsblk                # 看全局:每顆碟/分割區掛在哪(最右欄 MOUNTPOINTS)

不過 mount 指令的效果只到關機為止;要讓掛載「跟著系統」,必須寫進 /etc/fstab——開機時 systemd 照這份清單把每扇門重新打開。一行六個欄位:

UUID=3f5e02a1-…① 掛什麼:用 UUID
指認檔案系統 /mnt/data② 掛到哪:掛載點
(目錄要先存在) xfs③ 檔案系統類型
swap 分割寫 swap defaults④ 掛載選項
逗號分隔可加料 0⑤ dump 備份
一律 0 0⑥ fsck 順序
XFS 一律 0

為什麼堅持用 UUID 而不是 /dev/nvme0n1p1?因為裝置名稱是「開機時依偵測順序發的號碼牌」——加一顆碟、換個插槽,名字就可能全部位移,fstab 裡的舊名字會指到錯的分割區。UUID 是格式化時燒進檔案系統裡的身分證,永遠不變。

# blkid /dev/nvme0n1p1                                # 抄 UUID
# echo 'UUID=貼這裡 /mnt/data xfs defaults 0 0' >> /etc/fstab
# mount -a                                             # 立刻依 fstab 掛載 = 順便驗證寫對了
# findmnt /mnt/data                                    # 確認真的掛上

fstab 打錯字 = 下次開不了機(系統會卡在 emergency mode,也就是 boot-rescue 那題的劇情)。所以鐵律:改完 fstab,一定先 mount -a 或 findmnt --verify 驗過再收工。欄位格式忘了就 man 5 fstab。

6LVM:把磁碟變成積木池

傳統分割區的大小切下去就難改;LVM 在分割區之上加一層抽象——把空間打碎成固定大小的積木(PE),要多大就數幾塊給你,之後還能追加。三個名詞:

層全名是什麼指令家族
PVPhysical Volume交給 LVM 管的分割區(原料)pvcreate / pvs
VGVolume Group多個 PV 合成的大池子,切成等大的 PE(Physical Extent)積木vgcreate -s / vgs
LVLogical Volume從池子撥出若干 PE 組成的「邏輯分割區」,其上照常 mkfs + 掛載lvcreate / lvs / lvextend
# 三層各有查詢指令,考場隨時確認狀態:
# pvs ; vgs ; lvs
# vgdisplay wgroup | grep 'PE Size'    # 驗證積木大小

易混選項:lvcreate -l 100(小寫)= 100 個 extents;lvcreate -L 800M(大寫)= 800 MiB 容量。題目說「以 extents 指定」就必須用小寫 -l——這是 storage-lvm 評分明抓的點。

7swap:不掛目錄的特殊分割

swap 是記憶體的「溢流區」,它走同一套五層流程,但第 4、5 層換了指令:格式化用 mkswap(不是 mkfs)、啟用用 swapon(不是 mount)、fstab 的掛載點欄寫 none、類型欄寫 swap。

# mkswap /dev/nvme0n2p1                       # 格式化(輸出會印 UUID)
# echo 'UUID=貼這裡 none swap defaults 0 0' >> /etc/fstab
# swapon -a && swapon --show                   # 依 fstab 啟用並確認

對應練習:storage-swap。

考場動線建議:lsblk 看清現況 → 動手做 → 每完成一層就 lsblk 再看一次(分割出現了嗎?FSTYPE 對嗎?MOUNTPOINTS 掛了嗎?)——這個「做一步、看一步」的節奏能把錯誤攔在當層,不會做到最後才發現第一步就切錯碟。
