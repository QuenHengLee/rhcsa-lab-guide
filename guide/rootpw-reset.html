RHCSA · boot-and-recovery · init=/bin/bash 法

重設 root 密碼逐步詳解

「忘記 root 密碼」是 RHCSA 考綱明列的必考題(Interrupt the boot process to gain access)。你沒有任何登入管道,唯一的路是從開機載入器(GRUB)介入。這頁把每一步拆開講:要打什麼、會看到什麼、為什麼非這樣不可,以及每一步最容易卡住的錯誤。

原理:為什麼 init=/bin/bash 能免密碼進去

核心開機的最後一步,是把 PID 1(第一個程序)交給 systemd,再由它拉起登入畫面、要你輸入帳號密碼。我們在 GRUB 把核心參數改成 init=/bin/bash,等於告訴核心:「別叫 systemd,直接把 PID 1 換成一個 bash shell」。

於是系統一開機就落在一個 root 身分的 bash shell,完全跳過登入與密碼那一關——你就能直接進去把 root 密碼改掉。根(root 檔案系統)這時直接掛在 /,不需要額外切換目錄,操作很直覺。

先搞懂:什麼是「GRUB 選單」

GRUB(GRand Unified Bootloader)是 Linux 的開機載入器——負責在韌體交棒後,把 Linux 核心載入記憶體並執行。開機順序是:

按電源 → 韌體(BIOS/UEFI) → GRUB(選單在這) → 載入核心 → systemd → 登入畫面

在真正載入核心「之前」,GRUB 會顯示一個選單讓你選要開哪個核心——每一行就是一個開機項目(通常是不同版本的核心,更新後會保留舊版供回退):

*Rocky Linux (6.12.0-211...) 10   # 預設項(反白),倒數幾秒自動開
 Rocky Linux (6.12.0-舊版) 10     # 舊核心,可回退
 Rescue image                     # 救援模式

這正是重設密碼「唯一的入口」——因為它出現在「還沒進系統、還不需要密碼」的時機。所以整套流程都從這個選單開始。

兩個常見狀況:①選單常被設成 0 秒逾時、直接開機看不到——開機早期一直按 Esc(或 Shift)就能叫出來。②反白 ≠ 開機:方向鍵只是移動選擇;按 Enter 是正常開這項、按 e 才是編輯這項。重設密碼要按的是 e。
1

重開機,在 GRUB 選單按 e 編輯

開機時 GRUB 選單出現的幾秒內動作。

用方向鍵把預設的核心項目反白,按 e 進入編輯畫面(不是按 Enter——那會直接正常開機)。你會看到這個開機項的完整設定,包含一條很長的 linux 行和一條 initrd 行。

為什麼:GRUB 是唯一在「還沒進作業系統、還沒需要密碼」時就能介入的地方。按 e 讓你臨時改這一次開機的參數(改動不寫回磁碟,重開就恢復)。
2

編輯 linux 行:加 init=/bin/bash、刪 console=

找到以 linux 開頭、含 vmlinuz 與 root=/dev/mapper/rl-root 的那一行。

# 這條 linux 行很長,畫面上會「折成兩行」顯示,但它是同一條邏輯行:
linux ($root)/vmlinuz-6.12... root=/dev/mapper/rl-root ro crashkernel=...
  resume=UUID=... rd.lvm.lv=rl/root rd.lvm.lv=rl/swap init=/bin/bash
                                          ↑ 加在這條行的最尾端,前面留一個空格
initrd ($root)/initramfs-....img          # ← 這是「另一條」行,不要動它

兩件事一起做:(a) 移到 linux 行最尾端(Ctrl+e 跳行尾),空一格後打 init=/bin/bash;(b) 若行內有 console=tty0 console=ttyS0,把它們刪掉(見下方陷阱)。

為什麼加 init=/bin/bash:把 PID 1 從 systemd 換成 bash,一開機就是 root shell、跳過登入。
踩雷一:invalid file name 'init=/bin/bash'
你把它加到了 initrd 行、或自己按 Enter 另起一行。GRUB 就把 init=/bin/bash 當成「要載入的檔案」→ 找不到而報錯。修正:它只能接在 linux 行尾(rd.lvm.lv=rl/swap 後面),同一行、不換行。
踩雷二:進了 shell 卻打不了字(像當機)
沒刪 console=ttyS0。多個 console= 時,最後一個會成為 /dev/console;ttyS0 是序列埠,你的鍵盤打在圖形畫面(tty0)上,shell 卻在序列埠、收不到。修正:把 console=tty0 console=ttyS0 從這行刪掉(考試機常預設有,務必刪)。
3

按 Ctrl+x 用修改後的參數開機

編輯完成後送出。

# 開機後直接落在 root shell,提示字元像這樣:
bash-5.2#

看到 bash-5.2# 就對了——你現在是 root(PID 1 是 bash),但此刻的根檔案系統是唯讀的。

為什麼是唯讀:核心開機初期只以唯讀掛載根,確保檔案系統一致、可被安全檢查。下一步要改密碼(寫檔),必須先改成可寫。
4

把根重新掛成可讀寫

bash-5.2# mount -o rw,remount /
bash-5.2# mount | grep ' / '        # 確認開頭是 rw 不是 ro

rw 和 remount 順序不拘,mount -o remount,rw / 也一樣。最後的 / 是掛載點,不能漏。

為什麼:下一步 passwd 要把新密碼雜湊寫進 /etc/shadow。根還是唯讀就寫不進去。
踩雷三:passwd 時報 authentication token manipulation error
這正是「根還是唯讀」的訊號——你跳過了這步、或 remount 沒成功。修正:先把這步做成功(mount | grep ' / ' 顯示 rw),再回去 passwd。
5

設定新的 root 密碼

bash-5.2# passwd root
New password: redhat123
Retype new password: redhat123
passwd: all authentication tokens updated successfully.

輸入兩次新密碼(打字時螢幕不會顯示,正常)。看到 updated successfully 才算成功。

密碼太簡單時 passwd 可能會 BAD PASSWORD 警告,但身為 root 它仍會接受——警告完照樣要你再輸入一次確認即可,不影響結果。
6

建立 /.autorelabel 觸發 SELinux 重新標記

bash-5.2# touch /.autorelabel

在根目錄建一個空檔 .autorelabel。下次開機時 SELinux 會偵測到它,對整個檔案系統重新標記一遍,然後自動再重開一次。

為什麼這步最關鍵、最常被忘:你在 init=/bin/bash 這種殘缺環境改了 /etc/shadow,SELinux 的標記機制沒正常運作,/etc/shadow 可能被貼上錯的 context。SELinux enforcing 下,登入程式讀不了標記錯誤的 shadow → 你會發現新密碼「明明對卻登不進去」。touch /.autorelabel 讓系統重標一次,把 context 修正回來。
漏掉的後果:重開後用 redhat123 登入一直失敗、像密碼沒改成功。若真的漏了,再進一次 init=/bin/bash 補 touch /.autorelabel 即可救回。
7

交還 systemd,讓系統開完機

bash-5.2# exec /sbin/init

用 exec 把目前的 bash(PID 1)換成 /sbin/init(就是 systemd),系統於是繼續正常開機流程:偵測到 .autorelabel → 重新標記 → 自己重開一次 → 出現正常登入畫面。

為什麼用 exec:此刻 PID 1 是 bash,沒有 systemd 在跑,一般的 reboot/systemctl 不管用。exec /sbin/init 是最乾淨的「接手」方式。
備援:若 exec /sbin/init 卡住,改用強制重開:mount -o ro,remount / 然後 exec /sbin/reboot -f(先把根改回唯讀再強制重開,避免檔案系統受損)。

最後:確認成功

relabel 完、正常開機後,在登入畫面用 root / redhat123 登入。進得去就成功了。

# 練習環境(lab)裡用評分確認:
$ lab grade boot-rootpw
  PASS  root's password is now redhat123
  PASS  the system was rebooted after the reset
  ...

整套流程的心智模型

七步其實在回答四個問題,記住這條因果鏈就不會漏步:

怎麼免密碼進去GRUB 改 init=/bin/bash
怎麼看得到 shell刪掉 console=
怎麼能寫檔remount rw
怎麼改密碼passwd root
怎麼不被 SELinux 鎖touch /.autorelabel
怎麼開完機exec /sbin/init
三個最痛的雷,對應三個成功訊號:加對行 → Ctrl-x 不報 invalid file name;刪掉 console= → 進 shell 打字有反應;remount rw → passwd 顯示 updated successfully。每一步都等到成功訊號再往下,就不會白忙一趟。
